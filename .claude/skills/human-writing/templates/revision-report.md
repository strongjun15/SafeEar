# Revision report template

Use when the author needs to review and accept changes rather than take the rewrite wholesale — someone else's byline, regulated copy, or a draft you were asked to critique.

Keep it shorter than the text it describes. If the report is longer, hand back the rewrite and a three-line summary instead.

---

```markdown
## Revision summary

Length: <before> → <after> words.
Register: <unchanged | note the shift and why>.
Meaning: unchanged. <Or: name every place a claim's strength moved, and why.>

## Blocking

Changes that fix something misleading. Review these first.

1. **<short label>** — para <n>
   - Was: "<quoted span>"
   - Now: "<quoted span>"
   - Why: <the claim outran the evidence / a condition was dropped / a number was unsupported>

## Standard

Pattern fixes. Listed by pattern, not by instance.

1. **<pattern name>** — <n> instances, para <list>
   - Example: "<before>" → "<after>"
   - Rest applied the same way.

## Left alone

Things that match a pattern but were kept, so you know it was a decision.

- <span or habit> — <reason: author's voice / genre requires it / rewriting would lose a fact>

## Gaps to fill

Facts the piece needs that I do not have. Nothing was invented in their place.

1. <what is needed> — <where it goes>

## Open questions

<Anything where two readings were possible and I picked one.>
```

---

## Rules for filling it in

- Quote spans exactly. Paraphrasing a change the author is meant to review defeats the report.
- Group standard changes by pattern with one worked example each. Enumerating forty instances guarantees the report is skimmed.
- "Left alone" is not optional padding — it is what tells the author you read their voice rather than sanding it off.
- Never report a change you did not make, and never make one you did not report.
