# 프론트엔드 계정 연동

로그인 아이디 test11, 비밀번호 test11은 메모리 안에서만 동작하는 디자인 데모이다. 데모 기록은 실제 계정 API, 기기 저장소, 서버 동기화로 전달되지 않는 구조이다. 일반 계정은 기존 Supabase 인증과 실제 측정 경로를 사용하는 구조이다. 브라우저 미리보기에서는 일반 계정 서버를 연결하지 않으므로 로그인과 인증 메일 발송 성공을 모방하지 않는 상태이다.

회원가입은 이름, 아이디, 만 나이, 이메일, 비밀번호, 필수 동의를 받고 바로 로그인하는 흐름이다. 인증코드 입력과 재발송 단계는 제거한 상태이다. 백엔드 담당자가 Supabase 이메일 인증 설정의 Confirm email을 꺼야 가입 응답에 세션이 포함되어 바로 로그인되는 구조이다. 해당 설정이 켜져 있으면 화면에서 서버 설정 확인이 필요하다는 오류를 보여주는 방식이다. 실제 가입과 자동 로그인은 서버 연결 후 통합 확인할 항목이다.

만 나이는 인증 사용자 메타데이터의 age로 저장되며, 기존 계산 코드와의 호환을 위해 age_band로도 변환되는 구조이다. 기존 profiles 테이블의 열 추가는 없는 변경이다.

주간 리포트의 weekDays는 현지 시각 기준 최근 7일의 날짜, 요일, 청취 초를 제공하는 필드이다. 홈의 하루 청취 부담은 기존 주간 기준의 1/7을 기준으로 표시하는 방식이며, 피로 계산식 자체는 기존과 동일한 상태이다.

동기화와 모든 알림 종류는 기본 활성 상태이다. 알림은 사용자가 최초 안내에서 허용한 후에 요청하는 방식이다. 실제 운영체제의 최종 허용 여부는 시스템 설정에 따르는 항목이다.

튜토리얼의 다시 보지 않음은 기기 안에 계정별로 저장되는 설정이다. 선택하지 않으면 로그인할 때마다 나타나는 동작이다.

공식 인증 문서는 https://supabase.com/docs/reference/javascript/auth-signup 이다.


일반 사용자 화면 확인용 아이디 test, 비밀번호 test를 추가한 상태이다. 해당 계정은 실제 인증을 수행하지 않는 로컬 테스트 계정이며, 데모 기록, 가상 기기, 합성 소리 측정이 없는 빈 기록으로 시작하는 구조이다. 회원가입 아이디는 username 메타데이터로 전달되는 값이며, 실제 아이디의 중복 검사와 아이디 로그인 조회는 백엔드에서 연결할 항목이다.

프로필 사진은 선택한 이미지를 정사각형으로 줄여 계정별로 이 기기의 브라우저 저장소에 보관하는 방식이다. 다른 기기로의 프로필 사진 동기화는 백엔드 저장소 연결이 필요한 항목이다.
