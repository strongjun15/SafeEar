# 윈도우 앱 구조와 구현 결정

계획서(`docs/SafeEar_개발계획_v3.md`) 2절 파이프라인을 윈도우 앱으로 옮긴 방식, 그리고 계획서 9절의
**미해결 항목에 대해 코드에서 임시로 정한 값**을 정리한다. 임시값은 팀이 결정하면 한 곳만 바꾸면 된다.

## 1. 프로세스 구조

```
┌─ 엔진 창 (숨김 BrowserWindow, 별도 세션) ──────────────────────────────┐
│ ① WASAPI loopback (getDisplayMedia + audio:'loopback')                 │
│    실패 시 getUserMedia({chromeMediaSource:'desktop'})                 │
│    영상 트랙은 받자마자 stop() — 화면은 분석·저장하지 않음              │
│ AudioWorklet → 0.1초 묶음 → 1초 프레임                                  │
│ ② analyzeFrame(): A-가중 평균제곱 · 19대역 · 적률(β용)                 │
│    ▶ 밖으로 나가는 것: 숫자(특징값) + 파형 표시용 최소/최대 24점        │
└───────────────────────────────┬────────────────────────────────────────┘
                                │ IPC (특징값만)
┌─ 볼륨 도우미 (PowerShell + C#) ┼──────────────────────────────────────┐
│ IAudioEndpointVolume: 마스터 볼륨(dB), 음소거                          │
│ PKEY_AudioEndpoint_FormFactor: 헤드폰/스피커                           │
│ IAudioSessionManager2 + 미터: 지금 소리 내는 앱                        │
└───────────────────────────────┼────────────────────────────────────────┘
                                ▼
┌─ main 프로세스 ────────────────────────────────────────────────────────┐
│ Meter      SPL = dBFS(A) + 기준 SPL + 볼륨 dB → Pa² → 1초 선량          │
│            β(40초 창) → w(β) → 첨도 보정 선량                          │
│            MinuteAggregator → 1분 레코드                               │
│ RecordStore  userData/records/YYYY-MM-DD.jsonl (추가 전용)             │
│ SyncService  Supabase 업로드(1분) · 다른 기기 기록 받기(5분)           │
│ GaugeService 이 기기 + 다른 기기 병합 → F(t) · 이중 게이지 · 예측       │
│ Notifier     H.870 80%/100% · 쉬어가기 · 주간 리포트                   │
│ AuthService  이메일 / Google(루프백 + PKCE)                            │
│ Tray         창을 닫아도 계속 측정, 윈도우 시작 시 자동 실행 (--hidden) │
└───────────────────────────────┬────────────────────────────────────────┘
                                ▼ 1초마다 AppState
                          화면 창 (목업 v2 UI)
```

**원시 오디오가 엔진 창을 벗어나지 않게 코드 구조로 강제한다** (계획서 13.8절). 엔진 창의 preload가 내보내는
함수는 `frame / wave / status` 세 개뿐이고, 엔진 창은 별도 세션이라 화면 창에서는 캡처 권한 자체가 없다.

## 2. 크기와 모양을 따로 얻는다 (13.3절)

| | 출처 | 코드 |
|---|---|---|
| 모양 (β, 대역 비율, A-가중 비율) | 캡처한 파형 | `core/src/frame.ts` |
| 크기 (dB SPL) | dBFS + 기준 SPL + 윈도우 볼륨 dB | `core/src/calibration.ts`, `main/meter.ts` |

- WASAPI loopback 신호가 볼륨 적용 **전**인지 **후**인지는 장치마다 다를 수 있다 (9절 #11).
  기본은 "전"으로 보고 볼륨 dB를 더한다. 설정의 「캡처 신호에 볼륨이 이미 들어 있음」을 켜면 더하지 않는다.
  **Phase 0 확인 방법**: 음악을 틀고 윈도우 볼륨만 50% → 20%로 내렸을 때 앱의 파형 크기가 줄면 "후"다.
- 볼륨 도우미를 못 쓰면(학교 PC의 PowerShell 제한 등) 볼륨 100%로 가정하고 화면에 경고를 띄운다 (과대 추정 쪽).

## 3. 계획서 9절 미해결 항목 — 코드의 임시값

| # | 항목 | 임시값 | 위치 |
|---|---|---|---|
| 1 | 경고 컷오프 | H.870 80% / 100% (SafeEar·기존 중 큰 값) | `main/notifier.ts` |
| 2 | F(t) 스케일 | 주간 허용 선량 대비 %. 들어온 선량을 빠름 25% / 느림 15% / 7일간 남는 몫 60%로 나눔 | `core/src/gauges.ts` `DEFAULT_RECOVERY` |
| 3 | SPL 교정 | 볼륨 100%에서 0 dBFS RMS = 105 dBA, 불확실성 ±10 dB. 출력 장치별로 화면에서 바꿀 수 있음 | `core/src/calibration.ts` |
| 4 | 10년 뒤 EQ | ISO 1999 N₅₀(500~6k Hz)을 그대로 EQ 게인으로. 「볼륨 낮추면」은 −3 dB(에너지 절반) | `core/src/iso1999.ts`, `ui/audio-lab.ts` |
| 5 | 껍데기 색 하한 | #2의 60%(7일간 회복되지 않는 몫) | 〃 |
| 6 | 첨도 보정식 | Goley·Zhang형 w(β) = (β/3)^(6.5/10) | `core/src/kurtosis.ts` |
| 7 | β 창 길이 | 40초 이동창, 소리 있는 프레임만, 5분 지난 프레임은 버림 | 〃 |
| 8 | β < 3 | 배율 하한 1 | 〃 |
| (추가) | β 상한 | 100 (합성 임펄스는 β가 수백 → 배율 20배 이상, 문헌 범위 밖 외삽) | 〃 |
| 9 | 다기기 겹침 | 같은 분에 두 기기 이상 → 큰 값 + 겹침 표시 | `core/src/records.ts` `mergeRecords`, SQL `account_minutes` |
| 10 | 서버 위치·보호자 동의 | 서울 리전 권장, 만 14세 미만 가입 불가(필수 체크) | `docs/AUTH_SETUP.md`, 가입 화면 |
| 11 | 볼륨 적용 전/후 | 설정 스위치 (기본: 전) | 위 2절 |

그 밖의 구현 결정:
- **β는 A-가중 전 신호**로, 두 채널 표본을 한 모집단으로 합쳐 구한다.
- **청취로 세는 초**: 추정 SPL 25 dBA 이상이고, 음소거가 아니고, 출력 장치가 스피커가 아닐 때.
- **출력 장치 종류**: 윈도우 FormFactor 3·5·6 → 이어폰, 1·2·8·9 → 스피커, 나머지 → 미상(이어폰으로 계산).
  내장 사운드카드는 이어폰을 꽂아도 "스피커"로 알려 주는 경우가 많아, 화면에서 바로 고칠 수 있게 했다.
- **로그인 전 기록**은 이 PC에만 남고 업로드하지 않는다 (`owner_id = null`). 한 PC를 여러 사람이 쓰는 경우를 위해서다.
  기기 ID는 "설치 × 계정"마다 따로 만든다.
- **로컬 저장소**는 SQLite 대신 하루 한 파일 JSON Lines. 추가 전용이고 하루 180줄 남짓이라 네이티브 모듈 없이 충분하다.
- **AI-1 예측**은 아직 학습 모델이 아니라 베이스라인(지난 며칠 같은 시각 평균)이다 (`projectCrossing`). 계획서 5.2절의 비교 기준선.
- **콘텐츠 귀속**은 파형 분류(AI-3) 대신 윈도우 오디오 세션의 앱 이름으로 한다. 서버에는 범주만, 앱 이름은 설정에서 허용한 경우만.

## 4. 다기기 합산 (14.3절)

- 각 기기는 1분 레코드를 올리고, 같은 계정의 다른 기기 레코드(최근 7일)를 5분마다 받는다.
- 게이지는 매초 "이 PC 기록 + 받은 기록 + 지금 모으는 중인 분"을 `mergeRecords`로 합친 뒤 `integrate`로 다시 적분한다.
  F(t)가 선형이라 기기별로 나눠 적분한 합과 같다 (테스트 V9).
- 볼륨 추세는 **이 PC × 지금 출력 장치** 조합 안에서만 그린다 (14.4절 — 기기마다 볼륨 숫자의 의미가 다르다).

## 5. 검증 (계획서 8절)

`npm test` (core):

| 검증 | 테스트 |
|---|---|
| V1 선량 재현 | 75 dBA × 40h = 0.506 Pa²h, 80 dBA × 40h = 1.6 Pa²h |
| V3 첨도 무효화 | 가우시안 잡음 β ≈ 3 → 배율 1 |
| V4 회복 | 무음에서 빠름 e^(−t/30), 느림 e^(−t/240), 0으로 안 돌아감 |
| V8 이식 일치 | `test-vectors/` 골든 WAV + expected.json (다른 언어 구현이 통과해야 함) |
| V9 다기기 병합 | 한 기기 기록을 두 기기로 나눠도 F(t)·주간 선량 동일 |
| V7 EQ | ISO 1999 N₅₀ 값 확인 (EQ 응답 ±2 dB 비교는 아직) |

서버 스키마는 로컬 PostgreSQL에서 RLS 동작(남의 기록 읽기·쓰기 차단, 탈퇴 시 연쇄 삭제, 미성년 Mode 1 차단)을 확인했다.

## 6. 아직 윈도우 실기기에서 확인할 것 (Phase 0)

이 저장소의 코드는 리눅스에서 빌드·화면·계산 파이프라인(데모 소리)까지 확인했다. 아래는 윈도우 PC에서만 확인된다.

- [ ] loopback 캡처가 시작되는가 (상태 배지 「측정 중」), 어느 방식(`displayMedia` / 호환 모드)으로 잡히는가
- [ ] 영상 트랙을 멈춰도 소리가 계속 들어오는가 (안 되면 앱이 자동으로 "끄기만" 방식으로 바꿔 재시도)
- [ ] 볼륨 도우미: 볼륨·음소거·장치 이름·이어폰/스피커·앱 이름이 맞게 나오는가
- [ ] 볼륨 적용 전/후 (2절의 확인 방법)
- [ ] 앱별 캡처 가능 여부: 유튜브(브라우저), 스포티파이, 멜론, 넷플릭스(브라우저/앱), 게임 — 계획서 15절 매트릭스
- [ ] 블루투스 이어폰이 "헤드폰"으로 잡히는가
- [ ] 창을 닫고 몇 시간 뒤에도 측정이 이어지는가, 절전 모드 복귀 후 다시 붙는가
